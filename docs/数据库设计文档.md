## 三、数据表设计

### 3.1 用户表 (user)

存储用户账号信息。

| 字段名 | 数据类型 | 是否为空 | 默认值 | 说明 |
|--------|----------|----------|--------|------|
| id | BIGINT | 否 | 自增 | 主键ID |
| username | VARCHAR(50) | 否 | - | 用户名，唯一 |
| email | VARCHAR(100) | 是 | NULL | 邮箱地址 |
| password_hash | VARCHAR(255) | 否 | - | 密码哈希值（BCrypt加密） |
| avatar_url | VARCHAR(255) | 是 | NULL | 头像URL |
| quota_used | INT | 否 | 0 | 已使用的优化次数 |
| created_at | DATETIME | 否 | CURRENT_TIMESTAMP | 创建时间 |

**索引**:

| 索引名 | 索引类型 | 字段 |
|--------|----------|------|
| PRIMARY | 主键索引 | id |
| uk_username | 唯一索引 | username |

**建表SQL**:

```sql
CREATE TABLE user (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '用户ID',
    username VARCHAR(50) NOT NULL UNIQUE COMMENT '用户名',
    email VARCHAR(100) COMMENT '邮箱',
    password_hash VARCHAR(255) NOT NULL COMMENT '密码哈希',
    avatar_url VARCHAR(255) COMMENT '头像URL',
    quota_used INT DEFAULT 0 COMMENT '已使用优化次数',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户表';
```

---

### 3.2 简历表 (resume)

存储用户上传的简历信息和优化结果。

| 字段名 | 数据类型 | 是否为空 | 默认值 | 说明 |
|--------|----------|----------|--------|------|
| id | BIGINT | 否 | 自增 | 主键ID |
| user_id | BIGINT | 否 | - | 用户ID（外键） |
| file_name | VARCHAR(255) | 是 | NULL | 原始文件名 |
| content | TEXT | 是 | NULL | 文件原始内容（用于展示） |
| original_text | TEXT | 是 | NULL | 待优化的文本内容 |
| structured_data | TEXT | 是 | NULL | 结构化数据（JSON格式） |
| optimized_text | TEXT | 是 | NULL | 优化后的文本内容 |
| target_role | VARCHAR(100) | 是 | NULL | 目标岗位 |
| file_format | VARCHAR(20) | 是 | NULL | 文件格式（PDF/DOC/DOCX） |
| created_at | DATETIME | 否 | CURRENT_TIMESTAMP | 创建时间 |

**索引**:

| 索引名 | 索引类型 | 字段 |
|--------|----------|------|
| PRIMARY | 主键索引 | id |
| idx_user_id | 普通索引 | user_id |
| fk_user | 外键索引 | user_id → user(id) |

**建表SQL**:

```sql
CREATE TABLE resume (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '简历ID',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    file_name VARCHAR(255) COMMENT '文件名',
    content TEXT COMMENT '文件原始内容',
    original_text TEXT COMMENT '原文内容',
    structured_data TEXT COMMENT '结构化数据',
    optimized_text TEXT COMMENT '优化后内容',
    target_role VARCHAR(100) COMMENT '目标岗位',
    file_format VARCHAR(20) COMMENT '文件格式',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    FOREIGN KEY (user_id) REFERENCES user(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='简历表';
```

**外键约束说明**:
- `ON DELETE CASCADE`: 用户删除时，自动删除该用户的所有简历

## 四、字段详细说明

### 4.1 password_hash

**为什么存哈希值而不是明文？**

安全考虑。如果数据库泄露，攻击者无法直接获取用户密码。

**使用BCrypt加密**:

```java
// 注册时加密
String hash = passwordEncoder.encode(rawPassword);

// 登录时验证
boolean match = passwordEncoder.matches(rawPassword, hash);
```

**BCrypt特点**:
- 同一密码每次加密结果不同（加盐）
- 无法反向解密
- 验证时对比哈希值

---

### 4.2 content vs original_text

| 字段 | 用途 | 示例 |
|------|------|------|
| content | 文件解析后的原始内容，用于展示 | 完整简历文本 |
| original_text | 用户选择优化的部分内容 | 某一段工作经历 |

## 五、数据库初始化脚本

```sql
-- 创建数据库
CREATE DATABASE IF NOT EXISTS ai_resume 
DEFAULT CHARACTER SET utf8mb4 
COLLATE utf8mb4_unicode_ci;

-- 使用数据库
USE ai_resume;

-- 创建用户表
CREATE TABLE user (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '用户ID',
    username VARCHAR(50) NOT NULL UNIQUE COMMENT '用户名',
    email VARCHAR(100) COMMENT '邮箱',
    password_hash VARCHAR(255) NOT NULL COMMENT '密码哈希',
    avatar_url VARCHAR(255) COMMENT '头像URL',
    quota_used INT DEFAULT 0 COMMENT '已使用优化次数',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户表';

-- 创建简历表
CREATE TABLE resume (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '简历ID',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    file_name VARCHAR(255) COMMENT '文件名',
    content TEXT COMMENT '文件原始内容',
    original_text TEXT COMMENT '原文内容',
    structured_data TEXT COMMENT '结构化数据',
    optimized_text TEXT COMMENT '优化后内容',
    target_role VARCHAR(100) COMMENT '目标岗位',
    file_format VARCHAR(20) COMMENT '文件格式',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    FOREIGN KEY (user_id) REFERENCES user(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='简历表';
```

## 六、常用查询语句

### 6.1 查询用户的所有简历

```sql
SELECT id, file_name, target_role, created_at 
FROM resume 
WHERE user_id = ? 
ORDER BY created_at DESC;
```

### 6.2 查询简历详情

```sql
SELECT * FROM resume WHERE id = ? AND user_id = ?;
```

### 6.3 统计用户简历数量

```sql
SELECT COUNT(*) as total FROM resume WHERE user_id = ?;
```

### 6.4 更新优化结果

```sql
UPDATE resume 
SET optimized_text = ?, target_role = ? 
WHERE id = ? AND user_id = ?;
```

### 6.5 删除简历

```sql
DELETE FROM resume WHERE id = ? AND user_id = ?;
```

## 七、数据库设计原则

1. **字段命名**: 使用下划线命名法（snake_case）
2. **主键**: 使用自增BIGINT，避免ID耗尽
3. **时间字段**: 使用DATETIME，默认CURRENT_TIMESTAMP
4. **外键约束**: 保证数据一致性，级联删除
5. **字符集**: 使用utf8mb4支持中文和表情
6. **注释**: 每个表和字段都添加注释

## 八、扩展考虑

### 8.1 后续可能新增的表

**优化记录表 (optimize_log)**:

```sql
CREATE TABLE optimize_log (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    resume_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    tokens_used INT DEFAULT 0 COMMENT '消耗的Token数',
    model VARCHAR(50) COMMENT '使用的模型',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (resume_id) REFERENCES resume(id),
    FOREIGN KEY (user_id) REFERENCES user(id)
);
```

**用途**: 记录每次AI优化的消耗，用于统计分析。

### 8.2 性能优化建议

1. 用户量大时，给 `username` 添加唯一索引
2. 简历量大时，给 `user_id` 添加普通索引
3. 考虑分表：按用户ID分表存储简历
